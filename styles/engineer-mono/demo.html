§ specifications
01 § 01 / 08 — Color

Near-monochrome, one violet.

True black surfaces. Five steps of white at decreasing opacity. Exactly one chromatic moment — violet — used only where interaction lives. Mint and amber appear for status only, never decoration.

// note

Background uses #0a0a0c, not pure #000 — the warmth keeps the eye relaxed during long sessions. Surfaces escalate: --surface-1 → --surface-3. Text never goes solid white-on-white; we use opacity scales (t1 → t5).

02 § 02 / 08 — Typography

Mono is the voice. Inter is the headline.

JetBrains Mono runs the body — every paragraph, label, kicker, and caption. Inter only appears at large display sizes, where it becomes the rare flash of warmth in an otherwise rigorous grid.

// rule

If the text is under 18px, it is JetBrains Mono. If it is ≥ 24px display, it is Inter at 600–700 with letter-spacing: -0.025em (tight). Never the inverse. Never another typeface.

// the inter rule

Sans only at display.

Inter shows up only when the type is large enough to feel like a moment — a hero, a section heading, a stat. At smaller sizes, sans loses its restraint and the page starts to feel like marketing.

// the mono rule

Mono is the default.

Body text is mono. Labels are mono. Buttons that look like keyboard shortcuts are mono. The page should read like well-written documentation — tight, uniform, almost typewritten.

03 § 03 / 08 — Buttons

Four voices. One accent.

Primary in violet for the single most important action. Secondary outlined for everything else. Ghost for subordinate links. Code-style for shortcuts that should feel like a keyboard.

// note

Hover state is a 1px halo + soft violet glow (box-shadow). Active state is scale(0.98) — barely there, the way a real key responds. Never use translateY on press; this aesthetic doesn't bounce.

04 § 04 / 08 — Inputs

Inputs that feel like a code editor.

Mono caret. Violet halo on focus. Tiny uppercase labels above each field. Toggles and checkboxes glow softly when active — just enough to read state from across a room.

// focus

Focus state is a 1px violet border + 3px violet halo (box-shadow: 0 0 0 3px var(--ac-lo)). Caret color matches the accent. The halo is the entire affordance — no labels move, no rings inflate.

// account-settings.tsx
Account settings

All input primitives — text, select, textarea, checkbox, radio, toggle — each in its monospaced form, with violet as the only chromatic affordance.

05 § 05 / 08 — Cards

Cards as documentation.

Each card opens with either a code snippet, an atmospheric orb, or a terminal session. Hover lifts the card 3px and bathes it in a soft violet halo — the only time the page brightens.

// hover

Cards rest at --surface-1 with --border. On hover, border becomes rgba(124,92,255,0.30) and a layered shadow appears — depth shadow for elevation, violet glow for warmth. translateY(-3px).

06 § 06 / 08 — Controls

Sliders thin as a hairline.

A 1px track, a 12px violet dot with a soft halo, and tabular-figure readouts. The player feels less like an iOS music app and more like a Linear command palette playing audio.

07 § 07 / 08 — Navigation

Sidebar that feels like a sidebar.

A vertical list of mono links, each with a keyboard shortcut. Active state is a 2px violet rule on the left edge — no fills, no rounded backgrounds. Tabs above carry a single fading violet underline.

// active state

Sidebar active uses a 2px violet rule at left: -0.875rem with a soft glow — the page literally bookmarks the row, the way vim highlights a line. Tabs use a linear-gradient 1px underline that fades to transparent at the edges.
